# 非 Lite 认证后的账号通道锁定

本次升级采用账号准入规则：同一 Linux.do 稳定用户 ID 一旦成功完成非 Lite 认证，此后只能使用非 Lite 登录。`official_verified_at` 保存首次确认时间，不提供用户或管理员解除入口。管理员也受此规则约束。

这不能证明尚未进行非 Lite 认证的账号属于青春版。`trust_level` 继续只表示等级；下游 `login_method` 仍表示该次授权实际采用的认证通道，不增加“真实青春版”声明。

## 数据与认证行为

- 追加迁移 `0005_dear_golden_guardian.sql`，仅增加可空的 `user.official_verified_at`，原用户 ID 和应用归属不变。
- 成功的官方认证事件、首次标记和相关待完成 Lite 流程的取消在同一个 D1 batch 提交。失败、拒绝及身份不一致不触发锁定。
- Lite 发起、回调、会话创建、授权码生成和最终令牌写入均检查持久账号状态。手动新凭据必须通过上游回调确认稳定 ID，不能通过用户名推断归属。
- 被锁定账号的旧 Lite 管理会话停止被接受；会话行和认证事件保留，避免误伤此前签发的令牌。Lite Access Token、ID Token 与 UserInfo 保持原快照和有效期。
- 已知归属的待完成 Lite 认证、授权请求和未兑换授权码永久取消。未知身份的候选事务在回调确认账号后执行相同限制。
- 现有 Connect 密文和 Client ID 唯一占位保留。所有者完成非 Lite 登录后可以查看绑定摘要或删除，但不能再验证、更新和使用绑定。
- 明确的凭据删除和账号禁用继续执行原有撤销规则。改名、日志清理、账号重新启用或凭据变更均不能解除锁定。

## 接口与界面

会话用户、管理员账号摘要与详情返回可空的 ISO 格式 `official_verified_at`。登录上下文返回服务端计算的 `lite_available`；未确认身份可进行 Lite 验证，已确认账号的 Lite 控件原生禁用。

拒绝 Lite 认证使用 `official_login_required`，页面提示“此账号已完成非 Lite 验证，请使用非 Lite 用户登录。”。被锁定账号进入 Lite-only 应用时返回 `official_only_account` 准入原因，显示“此账号不符合该应用的登录要求”，提供返回及切换账号。

旧 Lite cookie 只可用于计算登录页上的限制提示，不再代表可用的管理权限。取消请求的页面提供不携带旧授权请求的返回入口；不能通过重新加载或缓存复用恢复已取消授权。

Connect 密钥页隐藏提交／更新表单，保留摘要和删除。管理员列表和详情显示“仅可非 Lite 登录”及首次确认时间。非 Lite 白色次要按钮、Lite 绿色主按钮和现有页脚保持原样。

## 回填与上线顺序

迁移字段后先发布执行约束的新 API，再运行历史回填。仅使用仍能关联稳定用户 ID 的官方认证事件、明确成功的官方认证审计或最近一次已验证官方快照。用户名输入、失败日志和不明确资料不能作为依据；缺少历史证据的账号在下次成功官方认证时锁定。

回填与在线认证调用相同的锁定函数，以每个账号为一个原子提交，保留已经存在的时间，取消审计通过事件标识去重。运行方式及中断恢复见 [运维说明](operations.md#账号非-lite-验证锁定与历史回填)。维护代码仅在本机运行，通过远程 D1 绑定访问明确选定的环境，不加入正式 API。

必须核对新版本承载全部流量，并确认升级前已进入处理状态的 Connect 回调结束。完成线上检查后再执行最终回填及幂等复查。单次 `remaining: 0` 不代表所有旧写入已结束。

## 验证记录

本地完成 Lint、类型检查、构建、217 项 Workers/API 测试、16 项部署脚本测试，以及 64 项桌面／移动端 Playwright 回归。独立安全／正确性审查通过，独立架构审查为 CLEAR。

覆盖成功／失败官方认证、稳定 ID 与改名、用户名复用、未知身份回调、账号启停、凭据删除、历史回填与重复运行。通过暂停数据库写入的方式验证 Connect 事务、回调、会话、授权码和令牌写入与账号锁定的两个提交顺序；批次中途失败时官方事件、标记和取消一同回滚。旧 Lite 令牌通过实际认证库验证来源与签名保持不变。

线上结果在部署验收完成后记录于 [发布记录](release-manifest.md)。模拟上游及合成身份测试不替代真人 Connect 登录，New API 联调和人工实际改名继续沿用既定延期／豁免。

## 回滚边界

字段和已确认的非 Lite 登录事实必须保留。不能回退到忽略该状态的 API，不能通过清空字段、批量撤销认证事件或删除全部旧会话实现回滚。修复版本应继续执行最终签发条件与既定历史令牌语义。
