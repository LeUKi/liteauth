# Upgrade Notes: 2026-10-06

This public note summarizes the stable-identity and administrator-detail upgrade without private deployment evidence.

## Stable Identity

Linux.do numeric ID is the durable account key. Username changes should update display data without changing LiteAuth account ownership.

Manual Connect credential submission is resolved through the authenticated callback identity. Existing bound client IDs remain tied to their owner. Unknown username hints are used only to reduce accidental selection before callback verification.

## Credential Versioning

Credential deletion, replacement, and account disabling invalidate stale Lite self-app transactions. A callback started before a credential change must not restore a deleted or replaced binding.

The implementation uses a credential version/clock model so same-user credential changes can be distinguished from unrelated users' changes.

## Administrator Detail Views

Administrator views include:

- stable LiteAuth user ID,
- current Linux.do profile fields,
- latest authentication snapshot,
- current Connect client ID,
- credential history,
- Connect verification records,
- applications created by the user.

Administrator reads of another user's details must not reveal upstream Connect secrets or downstream confidential-client secrets.

## Connect Verification Audit

Connect verification records separate:

- the actual identity returned by upstream Connect,
- the expected or target identity,
- the downstream authorization request, if any,
- the verification purpose,
- the result and reason.

`identity_confirmed` means upstream returned a verified identity. It does not by itself mean the identity matched the expected target.

## Validation Boundary

The original private release contained automated and live deployment evidence. Public docs intentionally remove local evidence paths, real user identities, domains, Cloudflare resource IDs, and deployment version IDs.

Manual real rename testing was explicitly waived for this upgrade. That waiver is a release boundary, not proof that real rename interaction was executed.

NewAPI integration remained postponed.
